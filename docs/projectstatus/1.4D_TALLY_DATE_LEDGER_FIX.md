# Phase 1.4D — Tally Date and Ledger Filtering

Date: 2026-09-16

## Problem

The read-only `EXPORT / DATA / DayBook` request returned the same vouchers for different `SVFROMDATE`/`SVTODATE` values. For example, requests for `1-Apr-2025` and `1-Jun-2026` returned five vouchers dated `2026-09-10`.

## Root cause established

On the target TallyPrime executable (`1.1.7.1`), the DayBook report responds successfully but does not apply the supplied static date variables in this HTTP context. This was reproduced with the documented human date form and with the documented Uni-date form. The report therefore falls back to its active/default period instead of the requested period. `STATUS=1` is not evidence that the requested scope was applied.

The supplied `Import Data`/`ACTION="Create"` XML is unrelated to read-only report filtering and was not posted.

## Implemented safe fix

`TallyXmlVoucherProvider` now validates every parsed voucher date against the requested inclusive range. If Tally returns an out-of-range voucher, the provider throws `TallyProtocolException` with the requested and returned dates. Out-of-scope accounting data can no longer be silently accepted.

The existing request factory remains unchanged because no replacement report/collection or filter was verified; changing the XML by guess would violate the protocol rules.

## Evidence

| Request period | HTTP/Tally | Vouchers | Returned dates |
|---|---:|---:|---|
| 2025-04-01 → 2025-04-01 | 200 / 1 | 5 | 2026-09-10 |
| 2026-06-01 → 2026-06-01 | 200 / 1 | 5 | 2026-09-10 |
| 2026-09-01 → 2026-09-01 | 200 / 1 | 5 | 2026-09-10 |

The provider now rejects all three as invalid date-scoped responses.

- Date filtering: BLOCKED for the current DayBook HTTP path; fail-closed validation implemented.

- WPF live extraction: BLOCKED until the underlying date/ledger scope is trustworthy; mock providers remain intact.

## Remaining blocker and next action

A verified replacement transaction mechanism is still required: capture the target TallyPrime Day Book/Ledger Vouchers report definition or a supported collection/filter that demonstrably honors dates, then validate it against three controlled periods and one ledger. Until that evidence exists, the connector fails closed rather than returning incorrect data.
