### Loaded company identity

The verified read-only `List of Accounts` request with `AccountType=Groups` returned:

`SVCURRENTCOMPANY = Deneb and Pollux Tour and Travels`

The company provider now derives a `CompanyInfo` from that response. No unsupported company identifier was invented; the company name is used as the source identifier because this response did not expose a separate stable identifier.

### Groups

Request: `EXPORT / DATA / List of Accounts`, static variable `AccountType=Groups`, XML export format, with the selected company context.
Live result: 28 group records. Example: `Bank Accounts`, parent `Current Assets`, with a live GUID.

The parser supports Tally's attribute-based `GROUP NAME=...` representation and child `PARENT`/`GUID` fields.

### Ledgers

Request: the previously verified read-only `EXPORT / COLLECTION / List of Ledgers` request.
Live result: 4 ledgers:

- Cash
- Electricity Expenses
- Profit & Loss A/c
- Uttar Haryana Bijli Vitran Nigam

The parser now supports live attribute-based `LEDGER NAME=...` nodes and retains decimal balances when present.

### Voucher response normalization

Request: the documented read-only `EXPORT / DATA / DayBook` request with `SVFROMDATE` and `SVTODATE`.
The live response contained actual `Journal` and `Purchase` vouchers. The C# parser normalized voucher date, type, number, narration/party fields where present, and `ALLLEDGERENTRIES.LIST`/`LEDGERENTRIES.LIST` entries using `decimal` amounts and debit/credit direction.

The parser removes only XML 1.0-invalid control-character references found in a Tally free-text field so the response can be parsed; accounting values are not altered.

## PARTIALLY VERIFIED

### Small live sample

The CLI live probe selected the loaded company and parsed the real ledger list, then requested a one-day sample. It returned two normalized vouchers. The response was successfully parsed after safe XML sanitization.

### Group-to-ledger hierarchy

Group hierarchy is present in the live `List of Accounts` response. The current `List of Ledgers` collection response did not populate parent-group values for the four returned ledger records, so a complete live ledger-to-group reconciliation is not yet verified.

## BLOCKED / NOT VERIFIED

### Date filter semantics

The request used `SVFROMDATE=1-Apr-2025` and `SVTODATE=1-Apr-2025`, but the live response returned vouchers dated `2026-06-01`. Therefore server-side date filtering is **not verified** and the provider does not claim that the returned sample is date-scoped.

Required next evidence: test the exact DayBook/report request and date variables against TallyPrime's Ledger Vouchers/Day Book UI for a known date, then compare returned dates and counts. Do not use this provider for production date-range extraction until that discrepancy is resolved.

### Ledger filter

No live server-side ledger filter has been verified. The current safe provider retrieves the verified ledger collection; it does not claim server-side voucher filtering by ledger.

### WPF live preview and reconciliation

The WPF application still defaults to mock providers. A live WPF preview and Tally UI count/debit/credit reconciliation are therefore not claimed as complete in this phase.
