# Phase 1.2 — Read-only TallyPrime discovery

## Scope

Established the read-only discovery path from connection to company, groups, ledgers, date range, and voucher/transaction sample. No Tally write operation was added.

## Verified integration evidence

Official TallyHelp documentation was checked for XML-over-HTTP integration. It verifies configurable HTTP server ports, HTTP POST, `text/xml`, the `ENVELOPE`/`HEADER`/`BODY` structure, and the read-only `EXPORT` + `COLLECTION` request for `List of Ledgers`.

The verified request is implemented in `TallyXmlRequestFactory`. `TallyXmlHttpClient` posts to the configured host and port. Company, group, and voucher request identifiers/filters were not fabricated: the real providers return an explicit `TODO: VERIFY WITH TALLYPRIME` protocol error until a request format is verified against the target TallyPrime installation/version.

## Implemented

- Added company context, extraction scope, date range, progress, request, and result contracts.
- Added read-only XML request creation and HTTP transport with cancellation and structured failures.
- Added XML response parser for groups, ledgers, balances, and vouchers with decimal amounts, date-only dates, debit/credit direction, references, party data, and optional fields.
- Expanded mock providers with synthetic company, hierarchical groups, ledgers, balances, tax identifier, and voucher data.
- Added Core services for company, groups, ledgers, vouchers, and extraction orchestration.
- Added cancellation-aware extraction flow with scope filtering and progress reporting.
- Extended WPF MVVM UI with company/group/ledger selection, local ledger search, date range validation, extraction, preview grid, and cancellation.
- Configured SQLite at `%LOCALAPPDATA%\Tally Prime Connector\connector.db` for application-owned data.
- Added parser, date range, decimal, mock extraction, malformed response, and direction tests.

## Explicit limitations

- No live TallyPrime installation was available in this environment; real connection, company discovery, group discovery, ledger discovery, voucher discovery, and a real sample remain blocked/not tested.
- Group and voucher request formats, pagination strategy, and Tally-version-specific filters require verification before live implementation.
- Final ledger-wise Excel workbook formatting remains out of scope for this phase.

## Verification

The .NET SDK and Node.js/npm are not installed or available on PATH in this environment, so build, unit-test, WPF launch, and website build verification are blocked. Source-level contracts and mock tests were added but not executed.

The SQLite restore vulnerability reported for `SQLitePCLRaw.lib.e_sqlite3` 2.1.11 is addressed by explicitly pinning patched version 2.1.12 in the data project. Restore/build verification should be rerun in the developer environment.

## Security

All implemented Tally operations are read-only. No voucher, ledger, group, company, configuration, password, protected-data, memory, or database write path was added. Python remains downstream of normalized C# data and is not involved in Tally communication.
