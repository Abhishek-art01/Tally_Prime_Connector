## Candidates investigated

1. `EXPORT / DATA / DayBook` with `SVFROMDATE`/`SVTODATE`: previously tested and proven unreliable on this installation; different periods returned the same out-of-period vouchers.
2. `EXPORT / DATA / Ledger Vouchers`: no valid response/report definition was established from the installed release; it is not implemented by guesswork.
3. Voucher collection `TSPLVoucherColl`: current official TallyHelp JSON documentation identifies this as a voucher collection (`type=collection`, `id=TSPLVoucherColl`). A corresponding XML collection probe was attempted against `localhost:9000` with the confirmed company name and a one-day period, but the request exceeded the HTTP timeout and produced no verifiable response. Native JSON support is documented for TallyPrime 7.0+, while this executable reports file version 1.1.7.1.
4. TDL-defined collection/report: not implemented because the exact installed-release definitions and filtering semantics were not verified. Injecting guessed TDL would violate the no-fabrication rule.

## Mechanism selected

No replacement mechanism is marked verified in this phase. The existing C# XML DayBook provider remains available only behind strict scope validation.

## Implemented safety behavior

`TallyXmlVoucherProvider` now parses the response and rejects any voucher outside the requested inclusive date range. This prevents the known DayBook failure from silently reaching normalization or processing. The provider does not claim that server-side Tally filtering succeeded when it did not.
